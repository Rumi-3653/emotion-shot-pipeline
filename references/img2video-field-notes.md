# img2video 實測筆記 — 一支 48 秒短片燒出來的坑與解法

> 平台:Kling(Image 3.0 文生圖 / Video 3.0 img2video)、Suno、edge-tts。
> 同一支 8 鏡 9:16 國風 3D 短片,從 v1 到 v5 重生了五輪才乾淨。以下每一條的現象與修法都是實測,
> 成因分析則是推測,未經平台證實。平台會改版,原理層的(起幅、連戲、指令稀釋)比操作層的(座標、按鈕)活得久。

---

## 一、首幀 = 鏡頭運動的起點(起幅原則)

**規則**:img2video 的首幀只能畫「這顆鏡頭開始的那一瞬間」,不能畫終點,不能畫全程。首幀把完成品畫出來,影片就沒東西可演。

**實例**:
- 鏡頭「她端茶走到畫桌前,放下茶杯,指尖碰到筆桿」——首幀候選裡「手已經拿著畫筆」的那張是錯的,要選「站立、雙手只捧茶杯、完全沒碰筆」。
- 鏡頭「把茶倒進乾涸的洗筆罐,再沾筆」——首幀必須是「筆乾燥、罐內只有乾涸痕跡、茶還在杯裡」,不是「筆已沾濕茶色水」。

**落地**:揭示型(微距推開揭示全景)與過程型(畫面內容在鏡中發生不可逆變化:完成一幅畫、水暈炸開、東西打翻)鏡頭,`script.json` 必填 `first_frame` 欄寫 frame0 靜態畫面;`props` 對齊 frame0 可見狀態;挑圖時拿 `first_frame` 文字當對照表,不是拿 `action`。

---

## 二、連戲三機制

1. **`props` 逐鏡狀態鏈**:每顆鏡只列 camera 框內看得到的道具,寫「此刻狀態」。沒有這欄的典型穿幫:關好的盒子下一鏡自己開了、桌角的杯子憑空出現、倒乾的罐子又滿了。用 `templates/props.md` 維護全片狀態鏈,再逐鏡填進 json。
2. **`first_frame` 起幅欄**:見第一節。
3. **`appearance_note` 永不注入**:角色檔裡「道具外觀寫在 props 檔」「此角色不入鏡」這類作者備註,曾被整段注入 prompt 害生成跑偏。慣例:`appearance` 只寫恆定可視特徵並原文注入;備註一律寫 `appearance_note`,prompt 產生器看不見它。

**跨鏡鎖臉**:先生一張乾淨的主參考圖(正面或四分之三臉定裝照),之後每顆鏡的首幀都掛它當 Image Reference。不是「所有鏡用同一張首幀」。臉部特寫鏡是必鎖優先級;臉不可見或無角色的鏡(俯拍桌面、失焦輪廓)可免重生。

**會演進的畫 / 物(hero plate)**:片中若有一幅逐漸完成的畫、一道逐漸煮好的菜,用最能看清它的那顆鏡先生一張 hero plate,其他露出鏡掛它衍生。靠圖鎖不靠文字鎖——但見第四節的副作用。

## 三、motion prompt 寫「臉入鏡」會洩漏真人素材(最嚴重的一條)

**現象**:首幀圖本身完全乾淨(桌面 + 茶杯 + 畫,無人物),motion prompt 寫「鏡頭極緩下降貼近紙面,她低頭湊近的側臉進入畫面邊緣」,Kling img2video 在中段吐出一段**完全不同的真人**:黑髮、戴眼鏡、五官比例跟角色設定對不上。不是畫風漂移;疑似訓練資料洩漏或幻覺(推測,未經平台證實)。8 鏡只中 1 鏡,但這一鏡從 v1 一路活到 v4 沒被抓到,因為它被歸類為「臉不可見、免重生」。

**偵測**:下游工具的人臉隱私自動打碼是現成的 canary——3D CG 算圖角色不會觸發,真實可辨識人臉才會。全片複查用每 0.5 秒抽幀;拼成審片拼圖時格與格之間要留間隔,否則鄰格的角色會被誤判成「多一個人」。

**緩解**:
- 不在 motion prompt 裡寫「臉部特寫入鏡」「側臉進入畫面」這類明確指令;改寫成「只在畫面邊緣以極淺景深帶出髮絲 / 肩膀輪廓暗示,不要清楚拍到正臉」。
- 加角色鎖定句:「角色全程是同一個 3D CG 動畫算圖人物 <名>,<招牌髮色>」。
- 負面詞加:「真人臉孔特寫、真人手部攝影特寫、切換成真實攝影 / live-action、<跟角色相反的髮色>、眼鏡」。
- 通用負面句每鏡都帶:「避免憑空出現或消失的物件、額外的人物入鏡」(本管線的 Kling 模板已內建這句;角色鎖定句與真人負面詞跟角色相關,要按角色手動加)。

## 四、hero plate 當唯一 Image Reference 會帶偏整體畫風

**現象**:為了鎖畫作連戲,只掛「這是一幅水彩畫」的 hero plate 當 Image Reference,約半數候選整個畫面變成扁平動畫 / 漫畫 linework,連人物臉型都崩。Kling 把參考圖的**媒材**讀成了整體畫風指令,而不是只鎖內容。一顆鏡連跑 5 輪 10 張才收斂。

**解法(二選一)**:
- 維持 hero plate 單參考,但 prompt 大幅加強「三分之二側面坐姿、同時看到臉 + 完整畫作」+ 負面詞「絕對不是 2D 動畫 / 漫畫」硬擋。
- 改回掛角色定裝照當參考(風格穩定性 100%),畫作內容純文字描述。代價是畫作跟 hero plate 不會像素級一致,要接受些微妥協。

**雙參考更糟**:同時掛 hero plate(畫)+ 定裝照(臉),Kling 把兩張都當「內容」合成——畫紙上畫出了她的肖像。要鎖畫就只掛畫,角色靠文字。

## 五、Image Reference 對臉型只是鬆引導,不是硬鎖

- 即使掛上「正確答案」的真實參考圖,生出來的下巴 / 顴骨比例仍系統性偏向模型自己習慣的較長臉型,還會多出參考圖沒有的「銳利上揚眼線」取代規格要的「眼尾微垂帶倦意」。文字描述仍主導結果。
- **純文字迭代約 3 輪後明顯報酬遞減**:腮紅濃淡、雀斑密度、額頭皺紋有無、髮色,在各種修正間反覆震盪。第四輪一張意外把招牌髮色生成錯色——prompt 疊到 15+ 正面描述 + 25+ 負面詞後,模型隨機丟掉較早的約束去滿足較新的。**指令稀釋是真的**,寧可少寫幾句。
- **臉尖有一半是相機角度**:俯角很陡的臉部特寫,透視前縮會把下巴壓尖。改文字三輪沒用,加一句「平視角度,不要極端俯視仰視」才解。先排除運鏡再動文字。
- 預期:臉型比例、瀏海結構這類**結構性**特徵 2–3 輪能收斂且穩定;膚質、腮紅、細節飾品這類**質感性**特徵純文字磨不穩。到瓶頸就接受最佳候選存檔,備案是人工修圖或 face-swap(來源臉只用自己生成的定裝圖或有授權的素材,不用真人照片),不要無止盡磨。

## 六、3D 人物的風格詞

- 別寫「Pixar / Disney-quality」——會變西方卡通大眼萌臉。
- 要中國動畫電影質感,寫具體的美學參照(例:當代中國動畫長片的寫實成熟五官、matte 半寫實膚質、subsurface scattering)+ 負面詞排除 `Disney style, Pixar style, big round cartoon anime eyes, cute chibi proportions, glossy plastic skin`。
- 這套已寫進 `core/styles.py` 的 `guofeng_3d` preset,連同該片主角的臉型約束——換角色請改定錨。

## 七、平台操作與後製(會過期,但先記著)

- **Ratio**:掛了參考圖後 Ratio 鎖 Auto(跟參考圖比例走,參考是 9:16 就沒事);沒掛參考時頁面 reload 後 Ratio 常重置成 3:4,送出前必查。
- **送出確認**:要看到綠色「Task submitted」才算真送出;蓋版彈窗會吃掉點擊且無錯誤。工作單寫「全數完成」要用作品列表核對數量,曾有一鏡根本沒生成。
- **Native Audio 關掉**可省額度;img2video 通常自動繼承首幀比例。
- **5 秒檔配 6–8 秒鏡頭**:`setpts=(目標秒數/原始秒數)*PTS` 精確算倍率,再 `minterpolate=fps=24:mi_mode=mci:mc_mode=aobmc:me_mode=bidir:vsbmc=1` 補幀。別固定寫死 1.25x。
- **浮水印**:用平台的無水印輸出方案(付費層級或導出選項)。自行去除平台標識可能違反服務條款與 AI 生成內容標識規範,本庫不提供做法。
- **下載多段影片時別靠提交時間推哪支是哪鏡**,順序會反;下載後逐支核對內容。

## 八、配樂與旁白(下游,但跟情緒弧線直接相關)

- Suno prompt 的情緒詞用英文(`core/music_director.py` 的 `EMOTION_EN` 表),結構指示留中文給人對照。
- 挑版標準:開場收斂、高潮前有堆疊、高潮後有留白的優先;全程同動態的直接淘汰。brooding 開場 → 高潮 → 留白收,比全程高動態好聽。
- **留白處的 ducking 陷阱**:sidechain ducking 只在人聲響時壓音樂;設計上要「高潮水滴那一下音樂沉下去」,但那裡旁白正好靜默,配樂反而全音量——違反設計。解法是先給配樂做一條音量包絡(peak dip)再進混音,不要指望 ducking。
- **edge-tts**:base rate 用 `+0%` 當基準再用情緒 preset 位移;把「療癒」直覺寫成 `-15%` 會跟「沉 / 低語」preset 疊成 `-35%`,約 2 字/秒像唸經且總長爆掉。慢速實際長度比估計長約 1.5 倍,要實測迭代。句首省略號會被唸成停頓害尾段爆長,拿掉。負值參數用等號寫法 `--rate=-24%`。
- 旁白要逐句 `adelay` 卡秒數並防重疊,同時產 SRT;素材分開留(無聲畫面 + 純配樂 + 旁白)才好乾淨混音。edge-tts 的演技有天花板,嫌僵硬就升 ElevenLabs v3 之類的情緒標籤引擎。
